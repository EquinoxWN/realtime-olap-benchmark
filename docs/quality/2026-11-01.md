# Quality check 2026-11-01

The ten engineering rules, checked against the code at this commit.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Every call can fail | pass | ClickHouse HTTP: `urlopen(timeout=...)`, HTTP and network errors become `EngineError` with the server message, responses capped at 256 MiB (`engines/clickhouse.py:83-91`). Doris/StarRocks: `connect_timeout=10`, read/write timeouts (`engines/mysqlfamily.py:96-98`). `drop_os_cache` runs with `timeout=120` and `check=True` (`harness.py:68-72`). Readiness polling is bounded by a monotonic deadline (`harness.py:180-188`). The `except EngineError` blocks are deliberate and recorded: unsupported cache drops are probed once and skipped, rejected session settings are listed in the result (`rejected`), `ANALYZE` failures become warnings. No retries, so none to bound. |
| 2 | Writes safe to retry | fixed | Result JSON, the data `manifest.json` and `report --out` were written in place; a crash could leave a truncated file. Now `fsutil.write_text_atomic` (temp file + `os.replace`), used in `results.save`, `datagen.generate` and `cli._report`. Table files are rewritten whole and the manifest (written last) holds their SHA-256, so partial data is detected on load. `test_write_text_atomic_replaces_and_leaves_no_temp_file` writes twice and checks one file. |
| 3 | No race conditions | N/A | Single-threaded: one engine connection, one query at a time; engines run one after another in CI. |
| 4 | Don't trust the clock | pass | Query timings use `time.perf_counter` (`harness.py:98`), deadlines `time.monotonic`. The run's `started` stamp is UTC (`dt.datetime.now(dt.UTC)`, `harness.py:144`). |
| 5 | Read before changing | fixed | Env vars `CLICKHOUSE_URL`, `CLICKHOUSE_USER`, `CLICKHOUSE_PASSWORD`, `DORIS_HOST`, `DORIS_PORT`, `STARROCKS_HOST`, `STARROCKS_PORT` `DORIS_USER`, `DORIS_PASSWORD`, `STARROCKS_USER`, `STARROCKS_PASSWORD` are listed in the README; the four `_USER`/`_PASSWORD` names of Doris and StarRocks were read but not documented, now added. |
| 6 | Never break compatibility | pass | The result format is unchanged; `load` validates every field. |
| 7 | One source of truth | fixed | Generated data names its source (seed, scale factor, generator version, SHA-256 per table in the manifest). The README and results said 98 tests after a later fix added the 99th; corrected. Engine image digests are pinned once in `docker/compose.yml`. |
| 8 | No secrets, validate input | fixed | ClickHouse credentials go in headers, never the URL (tested). A non-numeric or out-of-range `DORIS_PORT`/`STARROCKS_PORT` raised a bare `int()` error; now `port_from_env` names the variable and the range (`engines/base.py`). Query files must be one read-only statement. |
| 9 | Tests that can fail | fixed | No skips or tautologies. 1 of 15 hand mutants survived; 1 test added for it, 7 for the fixes (table). |
| 10 | Re-verify | pass | `bash .tmp/check.sh`: ruff clean, mypy `Success: no issues found in 27 source files`, `107 passed`, pip-audit `No known vulnerabilities found`, `realtime-olap-benchmark: OK`. CI (including the Docker `engines` job) in the commit history. |
